# better_virtual_imaging_plugin
A plugin for py4d_browser for better virtual imaging of 4D-STEM data.

## Installation
This is an external plugin for [py4D-browser](https://github.com/py4dstem/py4D-browser) -- install py4D-browser first, then install this on top of it:
```bash
pip install git+https://github.com/GeriTopore/better_virtual_imaging_plugin
```
The plugin is discovered automatically the next time you launch `py4DGUI`, and appears as "Better Virtual Imaging..." under the Plugins menu.

## Usage
Plugins > Better Virtual Imaging... opens a window with the settings in a column on the left and the previews on the right: in each preview, a diffraction pattern on the left and a virtual image on the right, as in the main window.

- **Virtual apertures:** turn on "Add Aperture on Click", then click a diffraction pattern to place a circular aperture of the chosen radius there. Drag an aperture to move it, use its handle to resize it, and right-click it to remove it. "Use BF radius" sizes apertures to the bright-field disk, measured from the mean diffraction pattern. The virtual image is the sum over all of a preview's apertures. Until a preview has any, it shows the main window's virtual image to navigate by. "Clear Apertures" removes them all.
- **g-vector arrays:** "g-Vector Array" puts apertures on the lattice spanned by two g-vectors. Drag the markers into place: O (starting at the bright-field disk's centre) and the tips of g1 and g2. Moving O carries both vectors with it. For each vector, set how many repeats the array extends either way along it, and a shift along it (e.g. 0.5 for half-order spots). "Include origin" adds an aperture on the direct beam. The array's apertures follow the radius setting and add to any click-placed ones.
- **Real-space cursor:** move it over the virtual image to choose which diffraction pattern is shown. It follows the main window's Detector Shape > Virtual Image setting: a point shows one pattern, and a rectangle shows the mean over it (or the maximum, with Detector Response > Virtual Image > Maximum).
- **Previews:** "Add Preview", above the previews, adds another below the others, each with its own apertures, array and cursor, so different aperture sets can be compared. Each keeps its full size however many there are -- as tall as the window allows, up to where its images are as big as its width allows -- and the rest are a scroll away. The wheel (or trackpad) scrolls the previews wherever the pointer is, even over an image; hold ⌘ (Ctrl on Windows and Linux) while scrolling to zoom the image under the pointer instead. Spin boxes in the previews only take the wheel once clicked into. The ✎ on a preview (or a double-click on its name) renames it -- the name is used in the merged view's key and in saved images, and clearing it goes back to the numbered default. The x removes it.
- **Pattern shown:** the menu at the top left of each preview switches its diffraction pattern between the one at the cursor, the mean pattern and the maximum pattern of the whole scan.
- **Merged view:** "Merge Views", next to "Add Preview", combines the previews with apertures into one view: their virtual images as a colour composite, and all their apertures on one diffraction pattern, each preview in its own colour. While merged, the "Merged Previews" list at the top of the settings picks which previews it shows -- untick one to leave it out (it keeps its colour for when it's ticked again). Click a colour in the key under the composite to change it. Click "Merge Views" again to go back to the separate previews.
- **Saving images:** "Save Image" on a preview saves a figure of its diffraction pattern, with its apertures drawn on it, beside its virtual image -- as shown, with the same scaling, levels and colormaps. On the merged view, it saves the pattern with every preview's apertures beside the colour composite, with a key to its colours. A dialog previews the figure and suggests `<dataset>_VI_preview_<n>.png` -- or `<dataset>_VI_<name>.png` for a renamed preview, and `<dataset>_VI_merged.png` for the merged view -- next to the data. Edit the path or choose one with "Browse..."; the extension sets the format (PNG, TIFF, PDF, SVG, ...).
- **Diffraction display:** Linear, Log (the default) or Power scaling for the diffraction patterns. Colormaps follow the main window's.
- **Binning:** "Bin Q" sums each N x N block of pixels in every pattern, and "Bin R" each N x N block of scan positions, with py4DSTEM's `bin_Q` and `bin_R`. It bins the main window's dataset too, and starts this window afresh; reload the file to undo it. Integer data are widened if the sums could overflow their type.
- **Bad pixels:** "Filter Hot Pixels" finds pixels that are hot in the mean pattern -- brighter than the second brightest pixel around them by more than the threshold, given as a multiple of the pattern's average intensity (py4DSTEM's `filter_hot_pixels`). "Fix Dead Pixels" finds pixels dimmer than the given fraction of the median of the 8 around them. Either replaces them, in every pattern, with the median of the 3 x 3 pixels around them (py4DSTEM's `median_filter_masked_pixels`), then shows the mean pattern before and after, with the pixels ringed: OK keeps the change, Undo puts the original values back. Binning and bad pixels need the data in memory, not memory-mapped.

### With Bragg vectors
If the file the dataset was loaded from also has Bragg vectors saved in it for the same data (for example by the Disk Detection plugin), the plugin also offers:
- **Show detected peaks:** marks the Bragg peaks detected at each preview's cursor with red dots -- every scan position inside a rectangular cursor.
- **Snap to Bragg peaks:** for a g-vector array, puts O, g1 and g2 on the peaks detected in the pattern shown -- all three when it's ticked or the array is first switched on, and each one when dropped near a peak.
